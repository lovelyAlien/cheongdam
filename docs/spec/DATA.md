| 캘린더 이벤트 | 아래 표 | S-03 블록 A, M-02, M-03 |

**캘린더 이벤트 (F2-7)**

| 이벤트 | 시점 | 제목 예 |
|---|---|---|
| 특별공급 접수 | `SPSPLY_RCEPT_BGNDE`~`ENDDE` (종일) | `[청담] ○○자이 특별공급 접수` |
| 1순위 접수 | 지역별(해당지역·기타경기·기타지역) 날짜가 다르면 지역마다 따로 | `[청담] ○○자이 1순위 접수 (해당지역)` |
| 2순위 접수 | 위와 같음 | `[청담] ○○자이 2순위 접수 (해당지역)` |
| 무순위·재공급 접수 | 접수 기간 (종일) | `[청담] ○○자이 무순위 접수` |
| 당첨자 발표 | `PRZWNER_PRESNATN_DE` (종일) | `[청담] ○○자이 당첨자 발표` |
| 계약 | `CNTRCT_CNCLS_BGNDE`~`ENDDE` (종일) | `[청담] ○○자이 계약` |

- 이벤트 설명: 청담 상세 링크, 청약홈 공고 링크, `일정은 정정될 수 있어요. 최신 일정은 청담이나 청약홈에서 확인하세요.`
- 이미 지난 일정은 넣지 않는다. 각 이벤트에 하루 전 알림(VALARM)을 넣는다.
- 이벤트 UID는 `공고번호-단계-지역@청담 도메인`으로 고정해, 다시 추가하면 캘린더 앱이 같은 일정으로 인식해 덮어쓸 수 있게 한다.

## 2. 추출 결과

1주차 실험(`experiments/pdf_extraction/extract.py`)의 분류와 줄 형식을 이어받는다.

| 필드 | 설명 | 예 |
|---|---|---|
| 분류 | 1 공통 자격 / 2 청약통장 / 3 일반공급 순위 / 4 특별공급 유형별 / 5 소득·자산 / 6 당첨 후 제약 | `1` |
| 제약 항목 코드 | 분류 6일 때만. 블록 B의 7개 코드 중 하나 | `rewin_limit` |
| 대상 | 적용되는 공급 유형 목록. `전체` 또는 아래 공급 유형 코드. 추출 지시문에서 이 코드 중에서 고르게 한다(자유 문장 금지). 코드에 없는 유형은 `기타`로 받아 검토 대상으로 표시한다. 출산특례·혼인특례·우선공급 같은 단계·특례는 대상이 아니라 요건 문장에 쓴다 | `["newlywed"]` |
| 요건 문장 | 80자 안팎의 쉬운 문장. 숫자·기간·비율은 원문 그대로 | `혼인 기간 7년 이내여야 해요` |
| 기준 표 | 소득·자산 조건의 기준 금액 표 (선택) | |
| 일반 규정 여부 | 「주택공급에 관한 규칙」을 옮긴 일반 정의·예외면 `true` | `false` |
| 근거 | `[{쪽, 문구, 검증 결과}]` 1개 이상 | `[{11, "…", true}]` |
| 상태 | 확인됨 / 확인 필요 (P-05) | |

- **분류 6 "당첨 후 제약"** 은 재당첨 제한, **1순위·가점제 제한**, 전매 제한, 부적격 당첨 제한, 중복 청약, **실거주 의무**, **계약금·중도금 비율·납부 시점**을 담는다. 1주차 실험의 추출 지시문(분류 6 "제한 사항")에는 뒤의 두 항목이 없으므로 지시문을 고친다(D-15).
- 1주차 결과에서 일반 정의(세대의 정의, 무주택으로 보는 예외 등)가 항목 수십 개로 나열되는 문제가 있었다. `일반 규정 여부`로 걸러 블록 C 맨 아래에 접어 둔다.

**공급 유형 코드**

`general_1st`(일반 1순위), `general_2nd`(일반 2순위), `newlywed`(신혼부부), `first_home`(생애최초), `multi_child`(다자녀), `newborn`(신생아), `elderly_parent`(노부모부양), `youth`(청년), `institution`(기관추천), `no_rank`(무순위), `resupply`(불법행위 재공급)

## 3. 툴팁 용어 (설명 초안, 법령 검수 전)

필터 칩, 블록 B 항목 이름, 블록 C 조건 문장에 나오는 용어에만 툴팁을 단다(D-13). 모바일은 바텀시트, 데스크톱은 툴팁(클릭 시 고정). 구성은 용어, 한 줄 설명(40자 안팎), 출처 법령, P-07 문구다. 한 화면에서 같은 용어는 처음 나올 때만 표시한다.

| 용어 | 한 줄 설명 (초안) |
|---|---|
| 특별공급 | 신혼부부·다자녀 등 정책적으로 배려가 필요한 사람에게 일반공급과 따로 먼저 공급하는 물량 |
| 일반공급 | 특별공급을 뺀 나머지 물량. 1순위·2순위 순서로 접수 |
| 1순위 / 2순위 | 청약통장 가입 기간·납입 횟수 등 조건에 따라 나뉘는 신청 순서. 1순위가 먼저 접수 |
| 해당지역 우선 | 공급 지역에 일정 기간 이상 산 사람에게 먼저 공급하는 것 |
| 무주택세대구성원 | 세대주와 세대원 모두 주택을 갖고 있지 않은 세대의 구성원 |
| 세대주 | 주민등록상 세대를 대표하는 사람 |
| 청약통장 | 아파트 청약에 필요한 저축 통장. 현재는 주택청약종합저축 |
| 신혼부부 특별공급 | 혼인 기간 7년 이내 무주택 부부 등을 위한 특별공급 |
| 생애최초 특별공급 | 세대 구성원 모두 주택을 가져 본 적이 없는 사람을 위한 특별공급 |
| 다자녀 특별공급 | 미성년 자녀가 여러 명인 가구를 위한 특별공급 |
| 신생아 특별공급 | 일정 기간 안에 출산·입양한 자녀가 있는 가구를 위한 특별공급 |
| 노부모부양 특별공급 | 만 65세 이상 직계존속을 일정 기간 이상 모신 사람을 위한 특별공급 |
| 청년 특별공급 | 일정 연령대 미혼 청년을 위한 특별공급 (주로 공공분양) |
| 기관추천 특별공급 | 국가유공자·장애인 등 관계 기관이 추천한 사람을 위한 특별공급 |
| 민영주택 / 국민주택 | 민간이 짓는 주택 / 국가·지자체·LH 등이 짓거나 주택도시기금 지원을 받는 주택. 신청 조건이 다름 |
| 전용면적 / 공급면적 | 집 안에서 혼자 쓰는 면적 / 전용면적에 계단·복도 등 함께 쓰는 면적을 더한 것 |
| 재당첨 제한 | 당첨된 사람이 일정 기간 다른 청약에 당첨될 수 없게 하는 제한 |
| 전매 제한 | 당첨된 분양권을 일정 기간 팔 수 없게 하는 제한 |
| 실거주 의무 | 당첨된 집에 일정 기간 직접 들어가 살아야 하는 의무 |
| 부적격 당첨 | 자격 요건을 갖추지 못한 채 당첨된 것. 당첨이 취소되고 일정 기간 청약이 제한될 수 있음 |
| 계약금·중도금 | 계약할 때 내는 돈과, 입주 전까지 나눠 내는 돈. 비율과 시점은 공고마다 다름 |
| 무순위 | 1·2순위 접수 후 남거나 계약 포기로 생긴 물량을 순위 없이 다시 공급하는 것 |
| 불법행위 재공급 | 불법 전매·공급 질서 교란으로 계약이 취소된 물량을 다시 공급하는 것 |
| 입주자모집공고일 | 공고가 게시된 날. 나이·거주 기간·무주택 여부 등을 판단하는 기준일이 되는 경우가 많음 |

- 규제 지역(투기과열지구·조정대상지역·분양가상한제) 용어는 규제 칩을 숨기는 동안(D-03) 쓰지 않는다. 칩을 노출할 때 법령 검수와 함께 되살린다.
- 세부 기준(나이, 기간, 자녀 수, 소득 비율)은 제도 개정이 잦아 툴팁에 숫자를 쓰지 않는다. 숫자는 공고별 추출 결과(원문 근거)로만 보여 준다. 예외로 "신혼부부 = 혼인 기간 7년 이내"처럼 오래 유지된 기준은 법령 검수 후 넣는다.
- **설명은 런칭 전에 법령 원문과 대조해 검수한다.**

## 4. 수집·정정·추출 정책

사용자에게 보이는 결과(노출 시간, 최신성)를 정하는 운영 규칙이다. 구현 방식은 [기술 노트 2장](../TECH_NOTES.md#2-기술-고려사항)과 담당 A가 정한다. 알림 정책(P-17~P-20)은 [ALERTS.md 4장](ALERTS.md#4-알림-정책)에 있다.

| ID | 항목 | 정책 (초기값, D-21) | 근거 |
|---|---|---|---|
| P-10 | 정기 수집 주기 | 하루 2회(06:00, 18:00 한국 시간) | 청약홈 공고는 주로 업무 시간에 등록된다고 가정. 아침 알림 발송 전에 수집을 끝낸다 |
| P-11 | 정정 감지 범위 | 모집공고일이 최근 60일 이내이거나 계약 종료일이 지나지 않은 공고를 매 수집마다 다시 조회하고 PDF 해시를 비교 | 접수 전후로 정정이 몰린다고 가정. 1주 운영 후 실제 정정 시점 분포로 조정 |
| P-12 | PDF 수집·추출 | 신규 공고와 정정이 감지된 공고만. 청약홈 요청은 초당 1건 이하 | 약관·부하 리스크([기술 노트 3장](../TECH_NOTES.md#3-리스크)) |
| P-13 | 추출 재시도 | 실패 시 1시간 뒤, 6시간 뒤 2회 재시도 후 "실패" 확정 | |
| P-14 | 노출 순서 | API 수집 즉시 목록·상세 헤더·블록 A 노출 → 추출 완료 후 블록 B·C 노출 | P-06 |
| P-15 | 수집 장애 표시 | 마지막 성공 수집이 24시간을 넘으면 목록에 업데이트 시각 경고(S-01) | 오래된 정보 제공 리스크 |
| P-16 | 공고 삭제 | API에서 사라진 공고는 즉시 지우지 않고 "청약홈에서 내려간 공고" 상태로 둔다(E-08) | |
