## 1. S-08 알림 구독·관리·해지

**목적:** 지금 보고 있는 필터 조건을 이메일 알림으로 저장하고, 로그인 없이 메일 속 링크로 관리한다(D-11).

**S-08a 구독 시트** (S-01 `이 조건으로 알림 받기` 또는 상단 `알림 받기`)

```
┌────────────────────────────────┐
│ 이 조건으로 새 공고를 알려 드려요   │
│ 서울·경기 · 신혼부부 · 5억 이하    │ ← 현재 필터 요약
│ ⓘ 무순위·재공급 공고는 특별공급    │ ← P-04 (해당할 때만)
│   정보가 없어 알림에서 빠져요       │
│ 이메일 [                      ] │
│ ☐ (필수) 개인정보 수집·이용 동의 › │
│ 매일 아침, 조건에 맞는 새 공고와   │
│ 정정이 있을 때만 메일을 보내요.    │
│ [      확인 메일 받기      ]      │
└────────────────────────────────┘
```

| 요소 | 규칙 | 요구사항 |
|---|---|---|
| 조건 요약 | 현재 필터를 한 줄로. 접수 상태 필터는 알림 조건에서 제외하고 `접수 예정·접수 중 공고만 알려요`로 고정 표시(새 공고는 항상 접수 전이거나 접수 중이므로) | F3-11 |
| 이메일 입력 | 형식 검사. 제출 후 `○○@○○로 확인 메일을 보냈어요. 메일의 링크를 눌러야 알림이 시작돼요.` | F7-1 |
| 동의 | 개인정보 수집·이용 동의(필수). 펼치면 항목·목적·보관 기간(P-09) | F7-1 |
| 제한 | 이메일 하나당 조건 3개까지(E-18) | |

**S-08b 구독 완료** (`/alerts/confirm?token=…`, M-01의 링크)

- `알림을 시작했어요. 내일 아침부터 조건에 맞는 새 공고를 알려 드려요.`
- 지금 조건에 맞는 접수 예정·접수 중 공고 수와 `[지금 공고 보기]`(→ 조건이 담긴 S-01).
- 토큰이 만료되었거나 이미 확인한 구독이면 E-14, E-16.

**S-08c 구독 관리** (`/alerts/manage?token=…`, 모든 메일 하단의 `알림 설정`)

- 이 이메일의 구독 조건 목록(최대 3개). 조건마다 `[목록에서 보기]`, `[조건 바꾸기]`(→ 그 조건이 담긴 S-01, 필터를 바꾼 뒤 `이 조건으로 저장`), `[이 조건 해지]`.
- 맨 아래 `[모든 알림 그만 받기]`.
- 이메일 주소는 가운데를 가려서 보여 준다(`ab***@gmail.com`).

**S-08d 해지 완료** (`/alerts/unsubscribe?token=…`)

- 메일 하단 `알림 그만 받기`를 누르면 확인 단계 없이 바로 해지하고 `알림을 그만 보낼게요.`와 `[다시 구독하기]`를 보여 준다. 그 메일이 속한 조건 하나만 해지한다. 모든 조건 해지는 S-08c에서 한다.

**관련 검수:** #18, #21, #22

## 2. 메일

### 메일 공통 규칙

- 발신자 이름 `청담`, 회신 불가 주소. 발신 도메인 인증(SPF·DKIM)을 갖춘다(PRD 8.1).
- 모든 메일 하단: P-07 면책 문구, `알림 설정`(→ S-08c), `알림 그만 받기`(→ S-08d), 데이터 출처. 메일 헤더에 `List-Unsubscribe`를 넣어 메일 앱의 구독 해지 버튼이 동작하게 한다.
- 링크에는 메일 종류를 담은 추적 파라미터를 붙인다(EV-12). 이메일 주소는 넣지 않는다.
- 제목은 사실만 쓴다. `놓치지 마세요` 같은 불안 조장 표현을 쓰지 않는다([문구 가이드 5.1](../SERVICE_SPEC.md#51-쓰지-않는-표현과-대체-표현)).

### M-01 구독 확인

- 제목: `[청담] 알림을 시작하려면 확인해 주세요`
- 본문: 구독한 조건 요약, `[알림 시작하기]`(→ S-08b), `내가 신청하지 않았다면 이 메일을 무시하세요. 확인하지 않으면 7일 뒤 자동으로 지워져요.`

### M-02 새 공고 알림

- 제목: `[청담] 새 공고 2건 · 서울·경기 신혼부부` (조건 요약은 20자에서 줄임)
- 본문: 공고마다 카드 하나.

```
[접수 예정] ○○자이 더 센트럴  민영
경기 수원시 · 3.2억~5.2억 · 59~84㎡
첫 접수 10.20(화) 특별공급
[상세 보기]  [📅 캘린더에 추가]
```

- 공고는 첫 접수일 가까운 순. 10건을 넘으면 10건만 싣고 `[N건 더 보기]`(→ 조건이 담긴 S-01).
- `캘린더에 추가`는 S-03 블록 A와 같은 .ics를 내려받는다.

### M-03 정정 알림

- 제목: `[청담] 정정 공고 1건 · ○○자이 더 센트럴`
- 본문: 공고마다 바뀐 항목(블록 D와 같은 `이전 값 → 새 값`). 바뀐 항목을 뽑지 못했으면 `공고문이 새로 올라왔어요.`
- 일정이 바뀌었으면 `캘린더에 추가한 일정이 있다면 다시 추가해 주세요.` + `[📅 캘린더에 추가]`.
- M-02와 같은 날 보낼 일이 있으면 한 통으로 합친다(P-19). 정정이 위, 새 공고가 아래.

### M-04 해지 완료

- 제목: `[청담] 알림을 해지했어요`
- 본문: 해지한 조건 요약, `[다시 구독하기]`. 모든 조건을 해지했으면 `이메일 주소는 바로 지웠어요.`(P-09).

**관련 검수:** #18~#22

## 3. 구독 데이터

| 필드 | 설명 |
|---|---|
| 구독 ID | 조건 하나당 하나 |
| 이메일 | 같은 이메일의 구독은 최대 3개 |
| 조건 | S-01 URL 쿼리와 같은 형식의 필터 조건. 접수 상태와 검색어는 넣지 않는다 |
| 상태 | 확인 대기 / 구독 중 / 해지 / 발송 중지(E-15) |
| 토큰 | 확인·관리·해지 링크용. 추측할 수 없는 무작위 값. 확인 토큰은 7일 유효 |
| 시각 | 신청, 확인, 해지, 마지막 발송 |
| 발송 이력 | (구독 ID, 공고번호, 공고 버전, 메일 종류, 발송 시각). 같은 공고·버전을 두 번 보내지 않기 위해 쓴다 |
| 발송 대기 | (구독 ID, 메일 종류, 담을 공고번호·버전 목록, 상태: 대기/발송 완료/실패, 시도 횟수). Python 배치가 쌓고 Spring이 읽어 보낸다 |

- 그 이메일의 확인 대기·구독 중인 구독이 하나도 없게 되면 이메일을 지운다(해지한 구독의 이메일도 함께 `NULL`). 7일 동안 확인하지 않은 확인 대기 구독은 행째 삭제한다. 발송 이력은 이메일 없이 횟수 집계용으로만 남긴다(P-09). 구체적인 파기 규칙은 [SCHEMA.md 6장](SCHEMA.md#6-알림)을 따른다.

## 4. 알림 정책

시스템 동작 정책(P-10~)의 알림 부분이다. 수집·정정·추출 정책(P-10~P-16)은 [DATA.md 4장](DATA.md#4-수집정정추출-정책)에 있다.

**누가 하는가** ([PRD 8.1](../PRD.md#81-기술-스택))

- **Python 배치(A):** P-17 시각에 P-18 대상 판단과 P-19 묶음·중복 방지를 적용해 구독마다 보낼 내용을 발송 대기 테이블에 쌓는다.
- **Spring(B):** 발송 대기 테이블을 읽어 메일(M-02, M-03)을 렌더링하고 NCP Cloud Outbound Mailer로 보낸 뒤 발송 이력을 남긴다. 구독 확인·해지 메일(M-01, M-04)은 사용자 동작에 맞춰 바로 보낸다. 반송 처리(P-20)도 Spring이 한다.

| ID | 항목 | 정책 (초기값, D-21) | 근거 |
|---|---|---|---|
| P-17 | 알림 발송 시각 | 매일 07:30(한국 시간) 한 번. 06:00 수집이 끝나지 않았으면 끝난 뒤 바로 보낸다 | 출근길에 확인. 18:00 수집분은 다음 날 아침에 함께 보낸다 |
| P-18 | 알림 대상 | **새 공고(M-02):** 직전 발송 이후 최초 수집되었고, 구독 조건에 맞고, 접수 예정·접수 중인 공고. **정정(M-03):** 직전 발송 이후 정정이 감지되었고, 구독 조건에 맞고, 계약 종료일이 지나지 않은 공고 | 추출 완료를 기다리지 않는다. 메일에는 API 데이터만 쓴다(P-06) |
| P-19 | 묶음·중복 방지 | 한 구독에 하루 한 통. M-02와 M-03이 같은 날이면 합친다. 발송 이력([3장](#3-구독-데이터))에 있는 공고·버전은 다시 보내지 않는다. 한 이메일에 구독이 여러 개면 구독마다 따로 보낸다(조건이 달라 내용이 다르므로) | 알림 피로 줄이기 |
| P-20 | 발송 실패 | 일시 실패는 1시간 뒤 1회 재시도. 영구 반송·스팸 신고는 그 이메일의 모든 구독을 "발송 중지"로 바꾼다(E-15) | 발신 평판 보호 |

## 5. 알림 예외

| ID | 상황 | 처리 | 관련 |
|---|---|---|---|
| E-14 | 구독 확인 링크를 7일 안에 누르지 않음 / 만료된 확인 링크를 누름 | 7일이 지나면 구독과 이메일을 지운다. 만료 링크는 `확인 기간이 지났어요. 다시 구독해 주세요.` + `[알림 받기]` | F7-1 |

| E-17 | 같은 이메일로 같은 조건을 다시 구독 | 새 구독을 만들지 않는다. 이미 확인했으면 `이미 이 조건으로 알림을 받고 있어요.`, 확인 대기면 확인 메일을 다시 보낸다 | F7-1 |
| E-18 | 같은 이메일로 4번째 조건 구독 | `알림 조건은 3개까지 저장할 수 있어요.` + 관리 링크를 메일로 보내 주는 `[알림 설정 메일 받기]` | F3-11 |

## 6. 검수 시나리오

번호는 상위 문서 1장 추적표가 참조하므로 바꾸지 않는다. #1~#17은 [SCREENS.md 6장](SCREENS.md#6-검수-시나리오)에 있다.

| # | 시나리오 | 기대 결과 |
|---|---|---|
| 18 | 구독 | 필터 → 알림 받기 → 이메일 입력 → M-01 수신 → 확인 링크 → S-08b. 확인 전에는 알림이 오지 않는다 |
| 19 | 새 공고 알림 | 조건에 맞는 공고가 새로 수집된 다음 날 07:30 이후 M-02가 한 통 오고, 같은 공고는 다음 날 다시 오지 않는다 |
| 20 | 정정 알림 | 조건에 맞는 공고가 정정되면 다음 날 M-03(또는 M-02와 합친 메일)에 바뀐 항목이 나온다 |
| 21 | 구독 관리 | 관리 링크로 조건을 바꾸면 다음 알림부터 새 조건이 적용된다. 이메일이 가려져 보인다 |
| 22 | 해지 | 메일의 `알림 그만 받기` 한 번으로 해지되고 M-04가 온다. 모든 조건 해지 후 이메일이 DB에서 지워진다 |
